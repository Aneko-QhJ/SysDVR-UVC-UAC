# 单次归档检查的读取复用候选（2026-10-23）

隔离候选通过26个原生场景，但本地对照没有可确认的速度收益，暂不接入实机。正常检查的实际文件打开/内容读取从3305次降到1757次，三次候选计时却与原版相近、略高。保留这一负结果，停止继续为该版本扩大模拟或准备实机。

新增4来源，总615；原611不变：`host/a23_archive_read_view.h`、`host/a23_archive_read_view.m`、`tools/a23_archive_read_view.py`、`tools/audit_a23_archive_read_view.py`。这些只用于隔离文件验证，不改真实两轮入口，不对当前97件快照发行新scope或授权。

## 候选边界

每次archive调用新建一个view：首先用POSIX目录遍历取得完整节点元数据（含隐藏项、`._`旁文件和目录），限定4096节点、全部普通文件合计64 MiB，拒绝symlink与其他类型。元数据比较device/inode/mode/uid/gid/nlink/size和mtime/ctime纳秒，排除读操作可能更新的atime。

第一次读取文件时使用只读NOFOLLOW/NONBLOCK打开；大小和类型检查、读取前后fstat、EOF及关闭结果均核对，再与初始路径身份比较。返回不可变字节；同一次archive后续读取复用这些字节，各调用自己的大小限制仍有效。结束时重新遍历并比较完整元数据表，拒绝可见的修改、替换、增加或删除，然后释放全部缓存。view只能完成一次，下一次检查重新打开所有归档文件，不跨轮保留内容或新鲜度声明。

只给archive派生helpers使用view；当前来源、基线、恢复索引、消费历史和job仍走原文件校验。协调器、driver、SDK操作与回执控制器未改。验收不声称原子目录快照、来源认证、最后检查后的永久新鲜度或回调排空；持续流仍未验证。

元数据边界不是恶意改写防护或所有并发交错证明。缓存命中不重读当时的字节；瞬时改写若避开所有观察，仍不能保证检测。它与原多遍读取不等价；原版也不是原子快照。以下仅是实际注入点的观察。

开发r1、r2正常候选被拒绝，均原样封存；URL目录枚举漏掉`._`旁文件。r2补充拒绝路径诊断，r3改POSIX遍历后完整清单通过。两份失败各两个原生进程均创建者wait，不追认通过；合计三版6个编译作业、30个文件重放进程，另6个链接检查进程均直接wait。最初一次相对路径CLI调用在创建输出前拒绝，无编译或fixture进程。

## 后续研究选择

暂停该读取复用版本，回到设备串行复用的下一项有信息增量的问题：新SDK在超过两轮时能否继续完成严格采集。先审查固定三轮方案的主机固定数组/配额、设备trace/owner容量和30秒诊断窗口，不直接增加无界轮数。

当前关联设备原件trace容量256、记录150；实测每轮两个STATUS和一个BURST在三个接口合计66条，加上18条前置记录。按同样请求形状，三轮估算216条，四轮282条超容量；这是容量可行性线索，不是后续无额外请求的保证。三个接口的前置流量、单请求17条预留和32 owner slots仍需按实际部署来源审核。旧主机driver及capability目前写死两轮，不能直接把次数改成三。

下一项只做这个三轮范围审查和最小候选设计，确定新范围、停止条件、证据容量及必要接线后，再审查并取得新的单次实测授权；不重复旧两轮成功，不继续扩展文件/进程通用框架。当前145..176耗尽、remaining0，SD已弹出，无新范围保留或授权。

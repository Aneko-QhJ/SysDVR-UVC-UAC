# 独立接口 2 诊断准备方案（2026-10-16）

本方案把[quiet 路径核验](A23_QUIET_PATHS.md)收敛为一次可审阅的分支取证流程，目标是
观察接口 2 是否读取目标 SETUP、在哪个早退/准入条件停止、是否更新 sequence、是否
提交 ISO，以及 ACK 停在哪一阶段。取得这些观察不等于认证 UVC 基线、长时间稳定性
或原超时根因。

**这是离线准备方案，不是已签发的测试。** 设备/接收器不改，既有 197 项回归结果保留；
所有票据和离线记录仍为零。未启动 acquire、访问 USB/SD、打包、部署或做硬件操作。

## 固定材料与范围

采用 quiet window-30s：运行 recipe ae65e7…，ELF 56778e…，NPDM 30e04e…，main 栈
请求 8192。接收器为 quiet schema 3，程序 0a99ee…，device binding e56f94…；六项
材料与当前/冻结源须匹配。完整摘要见 [接收器审查](A23_QUIET_RECEIVER.md)，不能用
旧 V3 构建、v1/v2 回执或原失败票据替代。

主机参数保持现有固定计划：HS、first_sequence=1、提前 64 个主机帧、960 个 transaction、
每项 192 字节；最多一次 ISO 提交、一次设备触发、一次主机异步 abort，不重试。
窗口不生产视频或音频，不另启视频/音频客户端。本方案不修改超时、控制请求或帧单位假定。

## 操作顺序（仅供未来获准后的独立运行）

| 阶段 | 操作与应记录材料 | 不满足时 |
| --- | --- | --- |
| 1. 确认构建与回收安排 | 核对六材料、接收器、配置、候选下次能从新进程启动，以及保存/Retained 后的回收办法 | 停留在准备阶段 |
| 2. 清除旧匹配实例 | 使旧候选实例结束并确认旧匹配接口已消失，不以旧进程重插线替代重新启动 | 不进入本次预等待 |
| 3. 预等待 | 仅使用将来另行签发的新可变记录启动一次工作流；记录先消费为 0，再产生回执和进程独占记录 | 启动/日志失败亦不退还次数、不再启动 |
| 4. 确认正在等新到达 | wait.jsonl 的 begin、注册、初始排空和 A23_E_WAITING（event=3）；旧匹配或多匹配会拒绝 | 停止本次，不人工选一个绕过检查 |
| 5. 新候选启动 | 在预等待有效时，以已确认的方式让候选新进程启动并出现唯一新接口；记操作顺序，保存后续 boot/session 身份 | 没出现、超时或 detach 时不重选 |
| 6. 一次交接与 SDK 开始 | selected→handoff；交接重新核对文件、回执、进程记录，provider 保持引用，关闭等待器，下一轮开始 SDK | 任何变化或不明引用均按原逻辑保留，不补发 |
| 7. 固定请求序列 | 一次 STATUS_before→主机帧号→ISO 入队→一次 burst→回调与保存→条件满足才 STATUS_after | 不手动补 STATUS/触发/取消以填齐记录 |
| 8. 结束与回收 | 分开记录主机关闭/保留、设备 window stop/双 join/保存结果，再按已确认的独立流程回收原字节 | 资源未明或文件未全时保留为失败/部分材料 |

预等待准备点是已有的持久日志事件，不新增 USB 就绪轮询。当前工作流没有 issuer；
封存 offline-record 仅作构建结果，未来的新可变记录不能通过修改这份封存取得。

## 几种时间不能混用

| 数值 | 代码含义 | 不能据此推断 |
| --- | --- | --- |
| 设备启动 sleep 20s | __appInit 中的启动等待请求 | 服务一定已就绪，或整个启动恰好 20s |
| 主机预等待 120s | 从 begin 计的唯一新匹配等待预算 | 设备窗口被延长到 120s |
| 设备窗口 30s | 视频 owner 建立 trace/session 后记录窗口起点；到期在调用前/返回后检查 | 从插线/主机启动时计，或正在执行的同步调用可被打断 |
| STATUS timeout 3000ms | 现有 STATUS 请求参数 | 可证明当前 recipe/boot 或设备剩余窗口 |
| burst control 16ms、ISO 2s | 主机本地完成观察阈值 | 原 16ms 失败必由某一设备分支造成 |
| 工作流观察 130s | 观察主机进程；超时保留且不 kill | 强制终止、设备已保存，或可安全取卡 |

仅 USB 重连不会重新初始化已结束的 30 秒窗口。UvcDeviceInitialize 位于 worker 启动
之前，唯一接口到达本身也不是“worker 已开始”的证明。STATUS_before 要求本地主机
观察顺序和 IDLE/seq0 字段新鲜，但其 168 字节不含 recipe、boot/session nonce 或
window start；不能把它当作新构建的身份/剩余时长令牌。

主机日志内部按 Mach clock 排序，设备记录内部按其 tick/frequency 排序。跨端只比
请求字节、顺序、sequence、身份及材料关联，不做两个时钟的直接相减。

## 应保留的原始材料

保留完整 run：消费回执、进程/SDK 独占记录、命令及 stdout/stderr、wait/session 日志、
入口结果、ISO 原始数据与 transaction 表、控制观察、final 或 retained 快照。
仍在变化或有未闭合进程的目录不能提前封存；稳定的失败原件仍应封存。不能用
kill/拔线充当正常释放证明。

设备侧取同一 nonce 对应的 `.execution.bin` 和 `.capture.bin` 或 `.diagnostic.bin`，
保留保存失败/部分文件与日志原字节，不混合两条出口。EXE3 内含窗口、启动关联、
主文件内容及保存 receipt；独立原主文件仍有比较价值。主机关闭不等于设备已完成
双 join/保存，单等 30 秒也不构成取卡许可。

当前 trace 是 **TRC2、256 条记录**；读取冻结候选源/新版解析器，不能套工作区 V1
原型的 128 条布局。检查 dropped/invalid、请求组和 helper 是否完整；缺失、溢出或
保存失败时，关于缺失阶段及完整链的断言应归入“不足以判断”，仍可描述已保留的
正向阶段记录。现有 simulation/diagnostic_only 和物理来源未认证字段保持原义，
不能为实采材料手工改成 hardware_verified。

## 结果判读表

目标 STATUS 为 `c1/51/0/2/168`，burst 为 `41/54/1/2/0`（前两项为十六进制）。
用同一 request_id 的 EVENT→CLEAR→SETUP→ISO_ENTER 及后续阶段判断：

| 观察 | 可以记录的结论 | 仍不能断言 |
| --- | --- | --- |
| 没有设备文件、trace 不完整/丢记录，或缺接口 2 目标 SETUP | 本次接口 2 分支未取得可判定证据 | 请求没到设备、总线没发包或一定发生覆盖 |
| GetSetupPacket result 非零 | 指定本地请求组读 SETUP 失败 | 失败的内核/总线根因 |
| 接口 2 SETUP/ISO_ENTER 有效，guard 给出错接口、busy、速度错误或非 HS | 已记录该条件的早退分支 | 该条件解释原失败的全部现象 |
| ISO_ENTER/speed 成功但无 sequence | 对照准入 observation/fault、记录完整性及停止边界，定位到 sequence 之前 | 仅凭无 sequence 指定准入失败或共享覆盖 |
| sequence=1 后 ISO_POST 失败 | 状态已更新，提交阶段失败并保留 result | 单凭 post 失败解释同一实例后续 seq0 |
| ISO_POST 成功，ACK helper 失败/未完成 | 提交与控制确认阶段已区分；看具体 clear/post/wait/report/parse | SDK 已成功完成控制，或 ISO 已传输成功 |
| ACK 返回成功但主机超时/零数据 | 分开保留设备 ACK、主机入队/回调和 transaction 字节 | 两端时钟可直接对齐，或已取得根因 |
| setup 混合到接口 0/1，接口 2 不同 | 当前记录呈现混合 SETUP，作为覆盖方向的证据线索 | 已证明总线/内核发生覆盖 |
| 整链内容一致、主文件/EXE3 完整 | 所供软件材料可关联，诊断分支具有可读记录 | 物理同 run、稳定 UVC 基线、自动批准下一次 |

sequence 的赋值发生在 ISO post 前；需要同时考虑准入、不同实例、复位/状态变化与
材料缺口，不能把任意 post/ACK 失败直接映射成原先的 IDLE seq0。

## 当前准备边界和下一项

离线程序、六材料关联、失败保留及必要路径已有审查。仍未确定实际内核栈预算、同步
调用时限或真实运行分支；当前也只有 ELF/NPDM 等离线产物，没有本次设备部署。
启动方式、部署文件清单、如何观察设备保存完成、Retained 时如何独立恢复/读卡，
需要在实机前形成可审阅的具体安排；本方案不以固定倒数或主机退出替代这些安排。

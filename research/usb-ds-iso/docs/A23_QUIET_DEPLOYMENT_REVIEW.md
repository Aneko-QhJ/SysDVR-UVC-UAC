## 新启动与停止安排

未来独立运行须有新授权和新可变记录，不能改封存零次数记录。一次的具体顺序为：

1. 按用户已确认的关机/恢复方式让旧实例结束并确认设备已关机，随后进行单独获准的
   卡操作。核对/备份实际基线，逐文件部署、读回验证、卸载并安全弹出，再装回卡。
2. 设备保持关闭且无旧匹配。主机先消费一次新记录并进入预等待，保存注册/初始排空/
   WAITING 证据，然后才按已确认的正常 CFW 启动流程启动候选。记录该人工操作。
3. 唯一新接口→交接→下一轮固定请求链；20s 启动 sleep 后仍有初始化，30s 窗口从
   owner 的 trace/session 起点计。接口出现不是 worker 就绪证明。USB 重插不会重置窗口。
4. 任一设备缺失/多匹配、身份变化、超时或资源状态不明，保持已有停止规则，不补发、
   重启工作流、再次取消或退还次数。保存稳定原件，变化中的 run 不提前封存。

`toolbox.json` 的 `requires_reboot:false` 只是原 UI 配置；本轮没有验证热停/热重载。
上面的启动方案选择关机后新启动，不依赖该字段推断 retained 资源可安全释放。
这里没有执行关机、CFW 启动、卡操作或设备访问，也没有认证某套具体按键操作。

## 保存与退出分开判断

设备文件位于卡根：`ep0-<boot16字节hex><session16字节hex>.execution.bin`，以及同名
`.capture.bin` 或 `.diagnostic.bin`。回收时保留全部原字节，包括部分/失败文件，并独立
核对文件名 nonce 与内容 nonce、运行 recipe、CRC、嵌套身份及主文件和 EXE3 内载荷。
新辅助工具只比较内容，不认证文件名、物理来源或同一次实机。

| 可见证据 | 可以确认的内容 | 仍未知 |
| --- | --- | --- |
| EXE3 解析成功 | 布局/CRC/嵌套身份和预期 recipe 在内容上成立 | 真机来源、双 join 实际返回、EXE3 自身提交 |
| 独立主文件与内载荷相同 | 两份所供内容一致 | 保存调用是否最终成功 |
| 主 receipt 的 commit_acknowledged=true | EXE3 内容报告主文件完成提交 | EXE3 自身提交、清理、进程已退出 |
| 主文件内容完整但 commit=false | 原代码可能读回正确后在提交失败处保留 | 不可归类为保存成功 |
| `.diagnostic.bin` 与 EXE3 均完整 | 可供分支分析的诊断内容 | 诊断出口即使保存成功也永远保留，不会正常退出 |
| 普通路径日志 `SysDVR-UVC exiting` | 代码中位于两个 save 返回成功及清理授权之后 | 单独日志不能认证清理完成/真实退出；缺日志也不是保存失败证明 |

没有已验证的在线“设备已保存完成”信号。主机关闭、130s 观察结束或等过 30s 均不构成
设备完成或取卡依据。完整 EXE3 字节在它自身最终 commit 失败时也可能留在盘面；
其自身提交不能靠自身 receipt 认证，当前格式没有这项证明。

若正常结束缺乏独立确认、出现 retained 或设备不响应，停止本次自动操作，保留主机
状态；需要用户另外确认的受控关机恢复，确认实际断电后再做只读回收。该干预可能
留下不完整文件，必须记录为恢复干预，不能改写为正常释放成功。未确认断电不取卡，
不以拔线/杀进程/再次请求来冒充正常完成。关机步骤和现场状态须在实机前单独确认。

## 本轮验证及后续研究

新增离线工具同时支持生成包、`--verify` 和 `--execution ... --primary ... --expected-recipe ...`
的只读内容判读。输出目录限制在研究 analysis 或 `/private/tmp` 的新规范路径，不能
指向挂载卡。包验证会复核完整文件清单和封存摘要、原六材料、接收器 binding、转换
段、NPDM、部署/回退文件及控制器补丁。所有状态保持 deployed/hardware_verified=false。

12 项新增测试及 209 项相关回归全部通过，无失败、错误或跳过。测试覆盖实际打包、段/容器/NPDM/补丁损坏、非离线路径、额外文件、正常/
诊断保存、两种 commit 失败、缺主文件、部分文件、错 recipe 和 CRC。回收样本沿用已
封存的 native 模型，recipe 为 `03` 后跟 31 个零字节，明确不是本次 ARM 候选实采。

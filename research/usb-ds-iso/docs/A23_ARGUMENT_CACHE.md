# 格式解析器局部入口与参数缓存审查（2026-10-14）

2026-10-15更正：本页旧工具标为x32/x64的局部取参区域实际由%o分支进入，不能当作
真实%x/%llx路径证据。新[转换路径审查](A23_PARSER_BRIDGE.md)已按实际分派接通正确
hex区域，并核验当前日志转换；旧工具和旧封存保持原样。以下保留原阶段观察。

本轮在[新ELF日志绑定](A23_LINKED_LOG_FILE_STATE.md)基础上，审查位置参数入口、参数
缓存及局部取值指令。两配置共338组指令profile通过。发现位置标志栈位置存在复用，
不能按全函数恒零剪枝；顺序参数缓存耗尽也不必然进入get_arg。没有证明整个解析器
会进入这些注入状态，因此没有从线程图删除get_arg或其他未知分支。USB根因仍未知。

## 当前日志与局部机器布局

新候选实际绑定73种格式，共97个转换，最多8个实参，使用d32/u32/u64/x32/x64和窄
字符串六种取值类型。格式不含位置参数或动态宽度/精度。额外d64路径仅作SDK局部
对照，并非当前日志格式。源码76种格式还含三条未绑定的UAC初始化日志。

`_svfprintf_r` 局部帧为1264字节：参数缓存从sp+752开始，32项×16字节=512字节，
保留区正好结束于sp+1264；缓存计数位于sp+308，初始化为0。这是局部帧布局，
不是带callee的格式化器或线程总栈界限。

位置参数标志在每次转换入口被置0，位于sp+136。但同一位置在后续分支还被三处
64位/成对写入复用。不能把整个函数中的该栈地址都解释为位置标志，或假定始终为0。
报告保存具体写入地址与指令。本轮只绑定该事实，尚未完成全函数栈位置存活区间划分。

## 数字扫描与取值路径

实际数字扫描片段有三处比较ASCII `$` 的位置，本轮回放其中处理数字宽度/位置索引
的一段。每配置8组，共16组：2x/4x/8x/12x/0008x保留位置标志0；1$d与32$u设标志1，
并产生从0开始的索引0/31；33$u在设标志之前进入索引拒绝出口。

这里只执行扫描片段，到重新分派或拒绝出口停止。0开头的宽度标志入口、完整转换
分派、字面文本扫描与错误出口均未完整执行。token、入口及位置状态由电脑注入，
不是运行完整日志得到的状态。

每配置161组局部取值profile，共322组，覆盖七种取值路径：

| 组别（每配置） | 数量 | 检查 |
| --- | ---: | --- |
| 当前索引0..7，两种ABI模式 | 112 | 原始值、计数与索引保持，无get_arg前沿 |
| 缓存索引31/32，两种ABI模式 | 28 | 31写最后一项；32绕过缓存，计数停在32，继续顺序取值 |
| 非位置参数缓存命中 | 7 | 直接读取缓存，不再次写入 |
| 位置参数缓存未命中 | 7 | 进入get_arg调用前沿，在调用处停止 |
| 位置参数缓存命中 | 7 | 直接读取缓存，不进入get_arg前沿 |

回放实际ARM取值指令，区分32位有符号扩展、32位无符号值、64位值与指针字节。
寄存器模式注入gr_offs=-56+8×index；索引6读寄存器保存区最后一项，索引7转向栈。
独立栈模式也核对取值路径。模型要求有效va_list/输入，内存读取必须已初始化，写入
必须位于参数缓存、计数、当前索引或va_list区域；缓存前后哨兵保持，SP不变。
指针路径只取指针值，没有解引用字符串。

缓存32项耗尽后，顺序分支跳过缓存写入、保持计数32、索引继续递增，并直接从
va_list读取，未进入get_arg。因此不能仅凭“缓存不足”归因get_arg，须同时审查模式
与索引条件。位置参数未命中的敏感性对照能到达helper，证明模型未一律屏蔽它。

## 结论的边界

这些profile绑定新ELF字节/函数哈希与实际代码位置，但入口处的位置标志、顺序索引、
缓存计数、ABI布局和实参值均注入。尚未证明73种格式通过完整解析器产生相同状态，
也未执行get_arg自身、完整格式化输出、SDK线程或Switch运行。

没有完整符号证明，不排除get_arg、错误/宽字符/浮点/重入或TLS路径；没有改写上一
阶段的通用条件调用图。FILE生命周期和整个线程栈仍未知，不能将本轮局部取值结果
作为整体栈安全证明。GetSize失败继续offset0写入的行为未修复。

16项新增Python核验包括ABI边界、有符号扩展、缓存31/32、位置参数命中/未命中、
数字扫描、实际字节篡改、放宽缓存上限时越界拒绝、未初始化读取与指令预算拒绝。
558项相关回归无跳过。旧源码、候选和封存保持，无新ARM构建、固件打包或USB/SD。

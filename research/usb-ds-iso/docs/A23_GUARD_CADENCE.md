# A23 显式校验边界与计时候选（2026-10-22）

后续接线：[导出双边检查、接受回执和独立收集器](A23_CHECKED_EXPORT.md)已通过独立控制器模型验证。下文“调用方尚未接入”描述为该阶段历史；新真实91件scope仍待准备。

电脑上的隔离原生模型已确认：保留下一轮前的完整校验，同时消除重复调用，可以把两轮之间完整校验从6次降为1次。26个候选场景、6个归档拒绝场景、2个校验前提场景及1个冻结逻辑对照完成，最终10项专项测试通过。新增4个来源，总601，原597逐字节保持。

本轮没有USB、SD、真实SDK对象、新实测许可、范围保留或新固件。模型仍用历史75件/113..144的临时副本和模拟namespace；当前卡证据为91件，真实113..144已经耗尽。模型中的重复数字不发行或释放真实序号。实测结论仍为[一次有限两轮复用](A23_LIVE75_FIRST_RESULT.md)。

## 改变的边界

旧coordinator guard先verifyScope，再经permit.result→healthy→verifier回调执行第二次verifyScope；状态getter还会重新触发完整校验。候选将许可回调改为verifyLiveJob，只核对当前scope、namespace树、作业和native claim；完整verifyScope由coordinator明确调用。

| 路径 | 候选行为 |
| --- | --- |
| 初始检查、begin之前 | 完整校验 |
| 无在途IO的tick之前 | 完整校验，然后允许等待、准备或arm |
| 在途ISO/control、包括失败保留状态 | 不做完整文件哈希，不读取活跃IO缓冲区 |
| 首轮保存之后 | 不在同一个tick立即arm；下一tick的完整校验通过后才提交第二轮 |
| result/finalStatus getter | 读取内存快照，不自动核对磁盘新鲜度 |
| finalizeOnce前后 | 各一次明确完整校验 |
| 最终导出 | 调用者必须在导出前后显式validateFinalExport；方法已验证，真实controller尚未接入 |

verifyLiveJob只有在verifyCore真正通过后才可使用。独立_coreValidated标记不接受verifyArchive成功作为替代；任何已观察到的失败保持锁死。许可仍只能claim/消费一次，native context的变化也可由permit stale拒绝，不要求所有错误都归为verifier failed。

getter的complete/saved只是上次状态快照；磁盘在此后变化时，getter可以仍显示旧值。调用者必须经过明确校验边界才能发布“当前通过”的结论。模型没有把这项语义变化接入旧真实入口，也没有将旧收集器视作新的校验凭据消费者。

## 原生验证

对照与候选均使用相同冻结假SDK前缀、真实文件校验/许可代码、临时根目录和ASan/UBSan。SDK时钟为合成时钟，完整文件校验另用主机CLOCK_MONOTONIC_RAW记录每次起止、耗时、阶段及结果；没有把两个时钟混用。

| 检查 | 观察 |
| --- | --- |
| normal、queued-delay | 两轮113..144、6144字节、四份STATUS留证及冻结严格分析通过 |
| 两轮之间的来源、基线、旧账本、前驱namespace、其他job、当前native context变化 | 只提交第一轮，第二轮拒绝 |
| 开始前历史、来源、回收索引、native文件等变化 | 首轮ISO为0 |
| 已失败文件随后恢复 | 失败保持，不重新开始 |
| pending或stopped-pending时来源变化 | 不做完整哈希；不提交第二轮 |
| 错误STATUS或载荷 | 只提交第一轮；错误STATUS168字节及具体失败字段保留 |
| 6个原始或重新封存归档坏件 | fake SDK打开和等待创建均为0 |
| 未做完整检查、仅做verifyArchive | verifyLiveJob均拒绝 |
| 最终封存前、封存后、导出后来源变化 | 显式最终检查拒绝，不能作为完整结果接受 |
| 重复消费与其他job接管 | 三份成功模型各两种重放均拒绝，namespace字节保持 |
| 连续读取状态getter | 候选16组重复读取不触发额外完整校验或作业检查 |

轮间计数窗口为“首轮回调已递送、执行保存tick之前”到“第二轮arm返回”。它包含保存步骤；在首轮尚在途时没有完整校验，因此统计到的完整检查对应保存后至下一轮前。夹具另加入一次result读取，复现真实controller在保存tick后的观察。对照为6次，两个成功候选均为1次。

本夹具直接驱动coordinator，未运行真实controller/timer。normal路径在导出前显式复核；after-export-source分支在写出后调用显式复核并成功拒绝。真实controller正常路径的前后双边检查、失败导出政策和新凭据格式仍待接线，不能将这个模型当作可启动实测包。

## 独立计时的含义

最终r2原生模型的成功完整检查耗时如下。数字来自一次顺序运行，含sanitizer开销，未做随机化或冷热缓存控制，不是实机性能对照。

| 模型 | 完整检查次数 | 最小 / 中位 / 最大 |
| --- | --- | --- |
| 冻结逻辑对照normal | 37 | 394.557 / 409.570 / 443.503毫秒 |
| 候选normal | 9 | 393.140 / 396.426 / 413.204毫秒 |
| 候选queued-delay | 9 | 395.163 / 396.916 / 443.865毫秒 |

次数减少已直接观察，真实轮间延迟尚未测量。单次完整检查在本模型中仍约0.4秒；现有候选也仍会在每次无在途IO的tick前做完整检查，因此仅去重并不足以证明连续流可行。此前实机1.476秒轮间区间没有独立哈希计时，不能拿本模型的中位耗时回填旧记录。

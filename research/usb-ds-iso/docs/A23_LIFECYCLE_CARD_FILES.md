# A23 生命周期候选部署与原件回收工具（2026-10-16）

已把[新包部署准备](A23_LIFECYCLE_PREPARATION.md)落实为独立文件工具，完成 16 个部署/回收场景及 32 项新增测试；309 项相关回归全部通过，失败、错误、跳过均为 0。完整结果保存在验证包。本轮只操作临时目录和既有封存材料，没有接触真实卡、签发正式记录、启动采集或执行设备程序；正式设备、接收器及部署包身份保持。

## 工具及现场输入

`tools/lifecycle_card_workflow.py` 提供 preview、snapshot、recover、deploy。导入模块或查看帮助不枚举磁盘，也不启动接收器。真实卷模式必须显式提供挂载点和分区；工具核对既定 SD UUID `37614F76-3E12-3470-B5C8-52B5A449C213`、外置 FAT 卷、挂载点及分区/整盘关系，读取 diskutil 的实际返回值，不固定假设仍为 disk4。

部署还要求 `--execute`、有效预部署备份和可写卷。独立回收要求系统报告该卷只读；工具不会自行卸载/重挂载来改变权限。预部署 snapshot 只读文件，但不要求卷本身为只读；备份记录绑定当时的身份和写入模式，之后模式或磁盘改变会拒绝直接部署，须重新核验备份。

DirectoryCard 模式只能使用 `/private/tmp` 下的临时目录。它的“弹出”是模拟状态改变，目录仍存在；只读标记也只是模型输入，不代表临时目录变为只读文件系统。演练生成 `A23-lifecycle-card-deployment-model-1`，正式签发要求 `A23-lifecycle-card-deployment-1`，因此演练回执不能作为实际部署凭据。

## 原件备份和回收

选取范围为该 sysmodule 内容目录、SysDVR-ISO 补丁目录、crash/fatal/erpt 报告树、根目录 logfile.txt 及所有根目录 ep0-* 原件，包括已存在的部分文件、临时文件和目录中的附属文件。保持相对文件名及原始字节，不删除旧证据，不生成替代 EXE3，不扫描 Nintendo/emuMMC 等其他树，也不声称整卡备份。

每次选取限制 4096 个文件、单文件 32 MiB、合计 256 MiB，并限制路径深度。非普通文件、符号链接、不支持的名称或超限会停止，不能静默跳过/截断后宣称已完整回收。输出只允许指定电脑端 card-cycles/deployments 的新直属目录，或临时模型目录；不能覆盖已有输出、写入卡内或扩展旧 analysis 封存。

预部署 snapshot 必须匹配最近回收确认的 quiet 四文件基线。复制后分别复查源卡身份、选取清单与内容，并读回全部电脑副本，再保存清单、阶段记录解析及校验封存。电脑副本与源卡稳定性分开检查；输出写入后仅有文件或仅有哈希清单，不等于原件复制成功。

recover 允许程序文件缺失或不匹配，保存原件并报告 mismatch；不因此丢弃部分 NSP、EXE3 或 LCP1。LCP1 各文件分别解析合法前缀，保留损坏、短头、缺失及多个文件，不自动选定某个 run。原件关联仍交给上一轮的独立收集器；CRC、文件名或记录内容自洽不认证物理来源。

回收默认不弹卡。显式选择 `--eject-after` 时，先完成电脑副本读回及源卡稳定检查，再核对并弹出同一目标整盘，确认挂载消失后封存 eject.json。复制或弹出失败可能留下有用但未封存的输出，不能标记完成或自动重做。`verify_snapshot` 可在目录移动后仅凭封存副本重核文件、清单、阶段解析和策略，不访问原卡路径；多文件摘要按文件名固定排序。

## 部署事务和失败

部署重新核对包、卡身份、quiet 四文件及全部选取原件与备份一致。先将四文件备份到电脑并逐字节读回，再持久化 intent.json。它只在 sysmodule 内容目录创建一个排他的新临时文件，写入/同步新 NSP 并完整读回；再次核对原卡内容与身份后，替换 exefs.nsp。其余三部署文件、日志、ep0 原件及报告必须保持。

替换后同步并读回全部选取文件，确认只有 NSP 改变；随后弹出对应整盘并确认挂载消失，才保存完整部署回执和封存。正式回执字段与已有第 4 代签发入口相容，但尚未用真实 Mac 卷跑通；本轮只证明临时目录事务及模拟系统返回值下的分支。

| 失败位置 | 结果及保留内容 |
| --- | --- |
| 错 UUID、内置盘、分区/挂载点错配、旧 A23/已是新版本 | 拒绝，不能按 quiet 基线覆盖 |
| 卡或原件在备份期间变化、电脑副本/备份读回不符 | 停止，保留已有电脑副本；不写 NSP |
| 临时 NSP 写到一半或临时读回错误 | 旧目标保持；保留临时文件、备份及失败记录 |
| 替换调用失败 | 记录调用结果，要求检查卡状态；不由失败返回推断绝无副作用 |
| 替换后同步或原件读回失败 | 新 NSP 可能已存在，保留现场和原备份；不自动回滚 |
| 弹出失败、弹错盘或挂载仍存在 | 不生成可供签发的成功回执，不自动重试 |
| 回执/封存写入失败 | 不能认证为完成；保留输出及证据，先检查状态 |

failure.json 的 `replacement_return_observed` 仅表示替换调用曾成功返回，不证明介质持久化；false 也不排除中断或异常调用已经产生副作用。进入写卡事务后的失败记录带有 `card_state_requires_inspection=true`；写前拒绝或备份失败可能仅留下未封存副本，但都不能当作成功。工具不删除残留临时文件、不自动恢复旧文件或补一次测试。预部署原件快照和四文件备份是后续受控恢复的材料，不是自动恢复授权。

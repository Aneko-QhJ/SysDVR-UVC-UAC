# 从有界 ISO burst 到 PCM：速率与调度缺口（2026-10-27）

后续进展：[固定16TD×24字节候选](A23_SHORT24_OFFLINE_CANDIDATE.md)已完成独立控制器、
完整设备ELF与15项离线检查；下文问题卡保留本次分析时的准备顺序，不代表已部署或实测。

本轮按[当前研究规则](RESEARCH_RULES.md)回到产品目标：免专用客户端的 UVC 视频与
标准 UAC 音频。Q1 的三轮成功支持底层有界传输；它没有传输 PCM，也没有证明连续音频。
本轮只分析电脑中的原件和源码，没有新 SDK 调用、USB/SD 操作、写卡、部署或实测授权。

结论：**仅删除轮间完整校验，仍不足以把当前串行接收器变成连续 PCM。**
需要同时解决包长/服务间隔与音频速率匹配、接收调度覆盖和跨捕获块的样本连续性。
这些问题比继续扩大通用额度模型更直接地约束下一项实现。

## 包长相同，不代表音频速率相同

PCM 目标为 `48000 × 2 × 2 = 192000 byte/s`。以下只做固定速率算术，未提供时钟漂移补偿。

| 形状 | 每服务机会的立体声样本帧 | 名义字节率 | 相对目标 |
| --- | ---: | ---: | ---: |
| 当前 A23：192 byte / 125 µs | 48 | 1536000/s | 8 倍 |
| 候选算术：24 byte / 125 µs | 6 | 192000/s | 1 倍 |
| 参考 UAC：192 byte / 1 ms | 48 | 192000/s | 1 倍 |

当前 16 包共 3072 byte，只有“相当于 16ms PCM 数据量”的含义。16 个 125µs
服务槽覆盖名义 2ms，首末槽相差 1.875ms。它们不是已测得的总线时长，更不是 16ms 的
连续音频。vendor 测试采用高密度图样是诊断形状，本轮没有将其改判为传输错误。

24 byte / 125µs 与 192 byte / 1ms 均只是名义速率匹配；前者尚未验证短包 producer，
后者不能由 A23 interval1 成功直接证明。标准 UAC 描述符、alt-setting、时钟和普通应用
验收仍独立存在。

## 当前串行节奏的实际差距

| 主机区间 | 第一轮 | 第二轮 | 第三轮 |
| --- | ---: | ---: | ---: |
| ISO 提交到入口回调 | 47.382834ms | 47.219792ms | 47.391250ms |
| BURST 到保存 | 51.616042ms | 50.473250ms | 51.272084ms |
| 保存到下一轮 before 意图 | 297.234209ms | 296.539125ms | — |
| 下一轮 before 意图到触发 | 2.331500ms | 2.812459ms | — |
| 两次 BURST 触发间隔 | 351.181750ms | 349.824834ms | — |

若将每轮 3072 byte 当成连续 PCM 的供给量，这两个触发间隔内分别只能覆盖目标需求的
4.556% 和 4.574%；字节等效缺口向上取整为 64355 和 64095。它们是同一主机时钟下的
供给预算，**不是实测丢失的音频样本数**；诊断没有音频源，也没有跨时钟总线校准。

反事实限定为“保留当前已观察的接收安排，每轮等上一轮回调后再提交”。即使把轮间工作
降到零，每轮仍有约 47ms 的已观察提交至回调等待，却只获得 16ms 的 PCM 等效字节量。
因此删掉约 297ms 的完整校验空档本身不能解决连续供给。47ms 不是 SDK 固有下限；
改变 lead、请求窗口、队列重叠或设备调度可能改变结果，本轮没有做这些实验。

这也说明“把第四轮加进去”不能单独证明连续性；旧 trace 容量和许可边界依旧适用。

## 旧音频路径还有独立的块边界问题

停用的 `UacDeviceSendAudio` 对每次调用的尾部独立补零，并始终提交完整 192 byte。
在每次成功捕获**恰为 4096 byte**的条件下：

- 单块为 21 个完整包加 64 byte 尾部；旧代码再补 128 byte 静音，输出 4224 byte。
- 每块多 32 个立体声样本帧，即 0.666667ms；样本总量相对源增加 3.125%。
- 三块原始 12288 byte 应为 64 包，逐块补零却输出 66 包，多出 384 byte / 2ms。
- 保留尾部并跨块拼接时，192 byte 包的三块输出数应为 21/21/22，余量 64/128/0；
  24 byte 包对应 170/171/171，余量 16/8/0。两者都能逐样本保留原始数据量。

`AbufSz=4096` 是缓冲容量，`CaptureReadAudioFrame` 实际返回 `dataSize`，并不保证每次
恰好满块；上述比例是明确输入条件下的静态后果。旧 UAC 当前禁用，不能声称本次 Q1
发生过音频变慢或插静音。后续实现必须依据实际长度处理余量，不能直接打开旧发送循环。

## 下一项：准备固定短包 producer，先不引入长期复用

优先保留已验证的 HS interval1，离线准备 **16 TD × 24 byte** 的独立候选，先回答
“现有 producer 能否在保持 TD 数量和所有权规则时完整处理较短载荷”。这一小步的
名义服务覆盖仅 2ms，不验收连续音频；之后才评估固定更长的一次性 TD 队列和接收覆盖。

| 证据与内存 | 单个有限提交，独立一次性 backing；完整保存空槽和原生错误。未交还不释放、不覆盖；沿用适用失败收尾 |

这是按照现有源码选择的最小离线准备方向，尚未证明24 byte可行。`iso_burst_context.S`
不仅检查描述符，还写死入口3072、TD长度192、地址步进192及ED完成192，因此不能仅改
描述符或主机请求长度。16位完成bitmap可在这一步保持；未来增加TD数则须重新审核bitmap、
ring容量和完整终结，不能沿用本问题卡直接扩展。

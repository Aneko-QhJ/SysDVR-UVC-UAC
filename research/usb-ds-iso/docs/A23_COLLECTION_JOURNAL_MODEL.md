## 事务与证据

日志按 `reserved → snapshotted → final_started → final_frozen → envelope_prepared → revalidated → completed` 顺序追加；每条记录绑定尝试摘要及上一条记录的摘要，排他写入并同步。原始监督记录、报告与静态内层收集格式复用上一阶段的实现，原有源码和封存原件保持原字节。

内层最终收集、外层 envelope 与整个 journal 分别提交。只有 journal 封存有效、阶段全部完成、没有失败记录且内层检查通过，才能判定事务完成。即使内层已有完整 `COMMITTED`，外层日志未提交时仍判为部分收集，不能获得完整模型链结论。

进程退出后的取证会复制日志到全新目录，冻结原始文件、空目录、部分输出、失败原因及分析；原日志和源尝试标记保持原字节。取证副本自己的 `COMMITTED` 只表示副本完整，不改变内部原事务的提交状态。检查器不补写、不清理、不恢复、不重试。

动态取证要求调用方持有已退出的文件 worker；仍在运行、未知 worker 或不属于该事务的 worker 均拒绝。作业原始字节摘要、源目录、journal、源模型 PID 与命令投递状态参与关联。显式静态取证继续标明没有观察到 worker 退出。普通摘要和 Python 对象关联不认证操作系统来源，`worker_origin_authenticated`、采集、清理与重试授权始终 false。

文件 worker 使用独立 Python 进程和精简环境；它只调用收集逻辑。该方式尚未形成操作系统级能力隔离，也不能阻止有权限的其他进程改写输入。路径替换竞争及启动后原工作区变化仍需继续研究。

## 验证

| 场景 | 结果 |
| --- | --- |
| 正常冻结证据、缺失报告证据 | 均完成文件收集；缺失报告保持模型链不完整 |
| 5 个阶段直接退出进程（退出码 73） | 原日志保持未提交，原始部分输出可只读封存 |
| 完整内层封存后、外层 journal 提交前退出 | 不提升为完整事务 |
| 注入写入失败 | 保留失败记录与尝试标记 |
| 内层收集后源文件变化 | 最终复核拒绝；不补写原日志 |
| 输入含符号链接、FIFO、超限报告或过多节点 | 扫描拒绝；扫描之前的尝试标记保留 |
| 保持 worker 阻塞 | 不创建取证输出；明确释放并退出后才取证 |
| 重复调用与半截源尝试标记 | 拒绝重试；原标记与日志字节保持 |
| 两个进程竞争同一源尝试 | 仅一个完成，退出码集合 0/2 |
| 关联其他事务已退出 worker、篡改作业 PID | 拒绝关联；有效作业摘要不能替代所属关系 |
| 显式静态取证 | 不声称观察到 worker 退出 |

14 个主要场景中，3 个完成收集事务、11 个保持部分收集；其中 2 个复用了已封存的完整假 SDK 链证据，缺失报告场景保持不完整。另有竞争、半截标记和静态取证检查。14 次重复调用全部拒绝，取证与重试前后原标记和日志保持。8 个篡改归档检查、新 17 项测试与上一阶段 17 项回归通过。

## 已实现的模型约束

- `GuardedBroker` 在启动前重新读取当前来源摘要，并复核两种构建角色；摘要必须与冻结构建的 392 项来源逐字节一致。来源或构建变化均在创建子进程、发行和模型消费之前拒绝。每次只允许一个启动尝试。
- 该复核是一个时间点的检查。它不锁定文件系统，也不保证启动后的原工作区不变；子进程仍验证私有模型输入。它不能充当生产环境的持续来源保证。
- 收集 API 只接收路径、已退出模型 PID 和命令投递状态，不接收 Popen、stdin、发行器或当前来源读取回调。独立读取器只检查文件，不启动接收器、不发行、不操作设备。这是 Python API 的职责分离，尚未形成操作系统级能力隔离。
- 已退出且流已收齐才允许进入收集；超时但未退出仍保留原监督所有权，不创建最终输出或收集尝试标记。测试中显式释放阻塞的假子进程，仅用于完成模型审查。
- 收集器要求已封存的监督退出记录，保留一个排他的持久收集尝试标记；模型及直接文件 API 的第二次收集均拒绝。未知启动结果不伪造成退出或提交。
- 内层仍使用显式静态模型收集格式，其 `producer_exit_reported=false`；外层关联监督退出记录、PID 和原始流。所有来源认证、真实采集及清理授权字段始终为 false。
- 报告合法且交接可用时，复用冻结的完整关联检查；报告损坏或缺失时封存不完整证据。原生 PID 替换仍会在外层被拒绝，即使内层假接收链单独有效。

## 验证结果

| 场景 | 报告/判定 | 保留结果 |
| --- | --- | --- |
| 显式注入策略的正常模型 | 对象/完整模型 | 假 SDK 两轮；真实采集授权仍 false |
| 实际策略拒绝 | 对象/不完整 | 实际沙箱查询结果 1；模型发行、WAITING、SDK 之前拒绝 |
| PID 替换、消费记录损坏、半条命令 | 对象/不完整 | 拒绝关联或许可，已消费模型不恢复 |
| 交接前退出、半条交接后退出 | 缺失/不完整 | 原生退出码 71、原始交接片段；没有模型消费 |
| 命令后立即退出 | 缺失/不完整 | 原生退出码 72、已消费模型记录 |
| 写半截报告后退出 | 无效 JSON/不完整 | 原始 `{"schema":` 字节、退出码 72 |
| 写数组报告或空报告后退出 | 非对象或空/不完整 | 两种状态分开记录、退出码 72 |
| 交接前超时、尚未退出 | 暂不收集 | 保留句柄；显式释放并退出后才收集不完整证据 |

共 12 个子进程场景（1 个注入完整模型、11 个不完整模型）、2 个启动前漂移拒绝、1 个启动失败、7 个篡改归档检查通过；新 17 项测试和旧 broker 16 项回归通过。逐项退出检查确认预期退出码、stderr 为空；ASan/UBSan 编译生效。

搬移整个冻结审查后，从搬移来源重新编译假 SDK 子进程，重新绑定接收与监督两个构建角色并重放全部场景、漂移拒绝和篡改检查。Python 文件打开审计禁止读取原工作区和 `/Volumes`；该检查不声称是原生进程的操作系统级文件访问审计。独立只读 CLI 的完整、缺失报告、损坏报告、伪造成功四种模式通过。

首轮审查暴露了一项路径限制错误：收集器把研究目录中的新输出也限定为 `/private/tmp`，在写最终输出之前拒绝。首轮冻结来源、已退出监督记录和错误日志另存诊断封存；最终版本仅要求模型生产目录位于 `/private/tmp`，输出仍要求规范非卷路径且与输入、构建不重叠。未覆盖的文件树大小超限、非普通文件或构建损坏仍拒绝提交，并保留尝试现场。

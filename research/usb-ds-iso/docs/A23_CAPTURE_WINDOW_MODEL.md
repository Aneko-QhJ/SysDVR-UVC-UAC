本阶段验证了一个明确边界：标记读完后，在日志读取期间修改或删除标记、替换源目录，首份冻结证据仍可显示完整。该结论只描述首份证据的内容，不能用作来源一直未变的证明。新增模型在首份取证之后和封存前分别复读源标记与 journal，比较内容摘要、目录清单、文件身份及元数据，以拒绝已经观察到的不一致。

## 判定含义

首份取证保留全部已捕获原始字节；后两次观察保存内容大小/摘要、目录清单、身份和稳定状态，不保存两份完整后续内容。因路径被替换而不能重读时，保留有类型的拒绝记录，不补写原件。

`observations_agree` 表示三次记录一致。`accepted_model_evidence` 只表示首份冻结模型链完整且观察集合一致，不授权采集，也不证明文件系统在整个期间未变。`atomic_snapshot_verified`、`source_unchanged_through_commit_proven` 和 `post_final_changes_excluded` 在所有场景中始终 false。

最后一次观察结束后，再修改标记的反例同样被保留：三次观察仍一致，但当前标记已经不同。这证明有限次复读不能消除最后一次读取到提交之间的窗口。该场景不被描述为来源原子快照、当前来源认证或生产准入成功。

## 验证场景

| 场景 | 结果 |
| --- | --- |
| 无变更 | 三次观察一致，可保留完整冻结模型证据 |
| 标记读取后、日志读取前修改/删除标记或替换源目录 | 3 个反例的首份取证仍完整；后续复读拒绝观察集合一致 |
| 首份取证后改动标记、改成链接、改动 journal 或替换 journal | 复读记录变化或拒绝，不读取替换目标内容 |
| 第一次复读后再改动标记或 journal | 第二次复读发现差异 |
| 标记字节改动后恢复、删除后用同字节重建 | 内容相同，身份或元数据变化仍拒绝 |
| 新增空目录 | 目录清单变化参与判定，不只比较文件摘要 |
| 首份证据本就不完整 | 即使三次观察一致也不提升为完整模型证据 |
| 最后一次观察后才改动 | 观察仍一致；提交期间未变及排除后续变化的证明始终 false |

15 个主要场景中，正常场景与最后窗口反例均保持观察一致且首份证据完整；其余 13 个不能获得该模型证据判定。最后窗口反例不证明当前来源有效。15 次收集重试和输出复用均拒绝，检查原件与既有输出未被拒绝动作修改。源文件变更由钩子在私有离线副本中明确注入。

7 个篡改归档检查、新 16 项测试和上一阶段 21 项回归通过。搬移 406 项冻结来源后，重放全部文件场景及只读 CLI 的正常、变更、首份不完整、最后窗口、静态、坏归档 6 种模式，分类一致。16 次成功取证调用（15 场景及静态模式）中，Python 文件打开检查没有发现源 `execution`、原工作区或 `/Volumes` 打开。该检查不声称是操作系统级访问审计。

首轮审查遇到测试脚本问题：它在“日志尚不存在”的不完整场景中仍尝试扫描该目录。首份及外层证据已完成封存，问题发生在审查的后续不变性检查；原始版本、错误日志和该不完整归档另存诊断。最终脚本把目录不存在作为应保留状态，不创建缺失日志。随后所有场景和篡改检查通过，但审查包共有 4231 个目录项，超过既有 4224 项上限；最终打包以较小的不完整证据承载无需完整链的结构篡改检查，维持原上限与 7 项拒绝检查。两个中间版本和日志均保留。

上一阶段保留了最后一次读取之后仍可改动文件的反例。本阶段给离线消费者提供独立的内容视图：以调用方给定的字节清单为合同，用捕获到的字节创建全新的排他文件，再一次性校验、读入不可变内存字节。后续消费者从该内存映射读取，不再次按路径打开原文件。

## 内容合同与来源范围

审查从上一阶段已封存的正常取证中选择 6 份确切材料：源尝试标记、journal attempt、副本、首事件、case-info 和一份 epoch-0 raw。它们的大小及 SHA-256 逐项对应原封存清单中的 `raw/` 项。另增加一个模型空目录来验证目录保留。

这只是固定字节消费实验，不是完整 USB 链或新的设备采集。视图合同由调用方明确传入；即使视图内部的合同和摘要一起被替换，验证仍必须匹配外部合同。来源原子快照、现场认证、物理同次运行和采集授权字段始终 false。

## 已实现的约束

- 通过目录描述符、`O_NOFOLLOW` 和普通文件类型检查读取。输入及输出普通文件的链接计数必须为 1；读取前后核对身份、元数据及链接计数。
- 新视图逐项排他创建文件并写入已捕获字节，提交前重新核对输出内容。不会用硬链接复用源 inode；异常、不安全树或合同不匹配时不提交。
- 消费者的加载操作从同一次描述符读取获得已验证字节，生成不可变 `bytes` 与只读映射；文件名集合、合同摘要和内容在受支持接口中不能改写。后续读取不访问文件系统。
- 输入在捕获后被改写或路径被替换时，已经捕获的合同字节仍可生成一致视图。该结果描述字节合同，不认证此刻的输入文件或设备状态。
- 视图在加载后被同权限程序改写、硬链接别名写入或路径替换时，已缓存字节保持；重新读取并校验磁盘副本会失败。文件系统并未被锁定，`os_immutability_enforced=false`。
- 同一输出不能覆盖或续写；三个显式发布中断点保留 ATTEMPT 和部分内容，无 COMMITTED，重试拒绝。两个进程竞争同一输出只有一个成功。

节点处理上限为 512，单文件 1 MiB、总内容 16 MiB；合同最多 128 个文件和 256 个目录，目录枚举在上限处停止。没有执行系统快照、不可变标志、权限提升或卷操作。

## 验证结果

| 场景 | 结果 |
| --- | --- |
| 正常复制与缓存 | 匹配外部合同；源与新视图 inode 分离 |
| 输入外部硬链接、输入内同 inode 别名 | 即使字节满足原清单，也拒绝多链接文件 |
| 文件打开后增加硬链接 | 读取后检查拒绝，未提交视图 |
| 源捕获后改写、发布后改写、捕获后替换源目录 | 视图仍保存给定基线字节，不把它标记为现场来源认证 |
| 提交前给输出增加硬链接或改写输出 | 拒绝提交 |
| 加载后直接改写、经硬链接写入、替换磁盘路径 | 缓存字节仍匹配合同；磁盘重新校验失败 |
| 输入缺失、符号链接、FIFO 或错误合同 | 拒绝发布 |
| reserved、copied、before_commit 进程退出 | 三种退出码均 75；原部分输出保留，重试拒绝 |
| 双进程竞争 | 退出码 0/2；唯一成功视图匹配合同 |

16 个主要场景中，7 个成功产生视图并验证缓存，4 个磁盘视图在观察时仍有效；其余 3 个已发布视图用于验证加载后的改写反例。另有 3 个进程中断场景、双进程竞争和 7 个篡改视图检查。所有输出复用拒绝，消费者接口的只读约束通过实际改写尝试验证。

新 16 项测试与上一阶段 16 项回归通过，共 32 项。搬移 410 项冻结来源后，重放全部场景、进程中断和竞争，结果一致。缓存读取的 Python 文件打开审计共覆盖 126 次读取，文件打开计数为 0；原工作区与 `/Volumes` 打开计数为 0。只读 CLI 的正常、已改磁盘、部分发布、自替换合同、伪造现场认证五种模式通过。该审计不声称是操作系统级访问控制。

审查归档会把工作副本内容复制进封存包；复制可能改变 inode 和链接数。硬链接场景的原始链接数及拒绝结果另存观察记录，搬移复核会重新创建对应别名验证策略，不从归档副本推断原 inode 关系。

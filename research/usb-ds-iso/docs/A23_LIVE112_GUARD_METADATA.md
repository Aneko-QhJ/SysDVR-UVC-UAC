# 固定128项三轮的完整校验开销与文件类型候选（2026-10-25）

新的本地分段表明，目录遍历中完整文件属性查询比SHA-256计算更昂贵。一个只把文件类型查询改为lstat的隔离候选，在本次交错重放中将完整校验均值从628.042 ms降到340.839 ms，约减少45.7%；每次成功仍读取3948次文件，未删哈希或每轮guard。这个结果值得接入独立候选，但尚未证明真实轮间间隔下降，也不是持续流。

本轮不改现场640来源或旧封存入口，仅分析321..368归档并在临时目录运行文件校验。112件冻结build的model roots从其自身档案重建，完整保留十个根与六个旧消费namespace。当前120件快照没有替换进旧build，不把归档重放称为当前现场freshness验证。

## 分段排除了哪些猜测

第一次重放保留全部文件算法，只增加分段、readFile调用/成功字节及digest内部时长。原版三次完整检查707.431/636.599/612.027 ms；分段版651.512/623.867/595.405 ms。单批、顺序执行，计时本身也有成本；不能拿这些本地数字直接替代真实163/164号时长。

分段版每次3948次readFile、返回36844253字节，3944次digest、送入SHA的36955649字节；重复digest和读调用并非一一对应。所有阶段SHA均值合计15.068 ms、摘要十六进制生成22.514 ms，绑定头文件/descriptor阶段34.387 ms。它们不足以解释总计约624 ms。这里是函数调用和返回字节，非物理磁盘IO计数。

第二次将archive目录检查拆开：完整遍历约350.006 ms，之后允许节点/目录前缀检查只有1.084 ms；不能把瓶颈归为目录前缀集合扫描。第三次才进一步测得：

## 隔离候选仅改变文件类型查询

保留Foundation目录枚举和原来的名称/节点数量、realpath、只读NOFOLLOW/NONBLOCK打开、fstat、大小、EOF、关闭、内容哈希、manifest、目录允许项、现场来源/基线/历史/job检查。只将files()中取NSFileType的属性字典调用改为lstat与S_ISDIR/S_ISREG；lstat错误或其他节点类型拒绝。没有跨轮缓存，也没有把元数据当作内容校验替代品。

原读路径通过打开时的fstat另行要求普通文件；目录仍必须是某个允许路径的祖先，额外空目录仍拒绝。新旧方案都不是原子目录快照，属性读取时刻与API不同，不声称所有并发交错下等价或恶意文件系统安全；本轮只验证下列实际安排，未把未观察到的瞬时变化保证补出来。

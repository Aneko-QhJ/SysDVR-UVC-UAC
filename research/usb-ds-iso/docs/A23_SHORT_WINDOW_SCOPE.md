## 缩短接收窗口的依据与限制

当前真实入口严格固定960个transaction，每项请求192字节，transaction结构28字节；每轮分配184320字节raw和26880字节transaction存储。A23描述符验证器要求HS endpoint0x83、MPS256、bInterval1；请求的192字节与端点MPS256是不同字段。部署设备仍固定发16包，每包192字节。仓库模板默认interval4不能替代实际入口的interval1条件。

按该服务间隔计算，960项对应名义120 ms，lead32帧对应32 ms；与约152 ms回调相容，但不是逐微帧时钟校准。SDK本机头文件只保证transaction表示frame或microframe，并说明中断延迟/负载可使多个transaction时间戳相同。不能把记录时间戳当作精确总线逐包时钟，也不能从旧960项归档证明新128项回调必在48 ms到达。

## 最小实现边界

实现应为新来源绑定的独立固定128候选，不修改已封存960入口，不把任意transaction数做成通用参数，也不允许旧scope静默接受新尺寸。

| 接线 | 必须同步核对 |
| --- | --- |
| transaction owner | 初始化尺寸、128项循环、enqueue计数、回调快照及transaction_count；保存全部128项和完整raw，错误/空槽不滤掉 |
| 三组SDK lease | 三份raw24576、三份transaction3584，原地址/不重叠/对齐/回调身份及每轮128项初值检查；任意interest仍停止 |
| 三轮driver | 构造及运行尺寸检查、enqueue固定128、快照验收全部128项、仍只接受16个192字节有效包；保持三轮STATUS/ISO7/URB唯一性 |
| 入口、许可与scope | 109原件基线、632及新增来源、完整49..272消费历史、五个旧namespace与新schema；拟273..320未保留 |
| 独立消费者与留证 | 新尺寸/transaction_count一致，旧960归档拒绝；三轮9216正确字节、六份STATUS、回执双边复核、失败owner快照和interest补充证据保持 |

固定三轮、lead32、BURST16 ms及ISO2 s期限、单次abort、每轮arm前完整检查、保存后下一次poll再arm均保持。128项名义16 ms窗口与控制16 ms期限恰好同数，二者用途不同，不相互推导。设备16包、30秒窗口及部署文件保持，不增加USB控制请求。

必要的离线检查仅覆盖新接线：正常128项三轮；960/127/129计数或尺寸混用在提交前拒绝；末槽载荷保留、15/17包及每项错误拒绝；三组存储/回调归属与旧回调不变；任一轮失败不提交下一轮；新旧归档/scope拒绝。保留原变化拒绝和导出检查，不扩展通用文件或进程框架。

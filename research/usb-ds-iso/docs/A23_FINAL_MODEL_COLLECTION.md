## 收集边界

受监督模型的父进程持有自己的`Popen`对象，确认子进程已退出后才执行完整文件扫描；仍运行或没有明确生产者模式时，在创建输出和扫描文件内容前拒绝。不杀进程、不取消请求、不自动重试。显式静态模式只将材料视为用户提供的模型文件，不宣称观察到进程退出。

独立只读复核CLI不运行归档中的程序，也不解析构建描述中的现场路径。它验证外部冻结构建的清单、来源、嵌入描述、头文件、二进制摘要和69基线，再重建scope，逐项检查归档清单、原字节、目录、消费回执、进程context、选择身份和最终接收检查点。构建单独提供，归档用摘要绑定；这避免为每个场景重复保存完整构建。

每个输出目录排他创建并持久写入ATTEMPT，收集原始失败/短写文件和空目录，不修复输入。提交前再次核对来源文件/目录、冻结构建和已退出子进程。短写或来源变化保留失败目录，缺少COMMITTED时不被视为有效归档；再次调用不能覆盖、补写或续阶段。两个收集进程争用同一目录时仅一个成功。

归档有效性与模型完整性分别报告：28个原生场景全部生成有效归档，2份模型链完整、26份不完整。运行中来源变化、驱动停止但请求状态不确定、原生context变更、坏载荷和最终回执变旧等均保留为不完整。原生进程异常退出的部分stdout/stderr也保存，不升级为完整结果。

`--require-complete`只读检查中，完整模型返回0，完整归档但执行不完整返回2且`archive_integrity_valid=true`，损坏归档返回2且该字段为false。一般取证收集成功不表示运行成功。

## 使用与限制

```sh
python3 -B research/usb-ds-iso/tools/collect_a23_two_epoch_final.py \
  --static-model /absolute/static-case --build /absolute/frozen-build \
  --output /absolute/new-collection
python3 -B research/usb-ds-iso/tools/analyze_a23_two_epoch_final.py \
  /absolute/collection --build /absolute/frozen-build --require-complete
```

这些入口只处理显式提供的静态模型；CLI不启动接收器。受监督子进程收集由模型审计驱动调用API验证。归档中的退出观察是所提供的证据，不是独立的操作系统证明；文件前后相同也不能证明没有其他写入者。原件与模型报告未经过物理来源认证。

退出后只收集已落盘的文件，不能恢复进程内存或证明原生回调排空；即使归档有效，`cleanup_authorized`、`callback_drain_verified`、`allow_retry`、`sequences_allocated`与所有硬件/正式发行字段仍false。现场故障收集、现场采集CLI及真实SDK生命周期尚未接通。

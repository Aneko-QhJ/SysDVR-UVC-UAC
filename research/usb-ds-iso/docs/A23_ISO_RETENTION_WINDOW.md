# ISO 错误保留与接收窗口审查（2026-10-17，Asia/Shanghai）

三次已保存的 SDK 测试具有同一条更具体的失败路径：**首 TD 匹配到 CC23，补丁锁存错误并保留请求**。在两端帧号属于同一总线帧域的条件下，三次主机窗口都比设备目标帧晚31帧。后续优先验证窗口覆盖假设；尚未确认根因。

本轮只分析既有材料、重建补丁并运行离线检查，无读卡、写卡或 USB 请求。正式记录仍 failed_no_retry/remaining0，SD 上次已安全弹出。

后续材料：[lead32接收器离线候选](A23_LEAD32_RECEIVER.md)已构建并验证，尚未新增实机测试。

## 已核验的错误分支

最新 STATUS 的 ISO7 112字节中，terminal=`80000017`，bitmap=`0000`，累计成功量0。原始错误事件为 `80023000 00000000 170000C0 00078001`：type32、endpoint7、ED=false、CC23、raw count192，匹配偏移0，即首个 TD。错误槽与 terminal 一致；不能把 raw count192 当作已传输192字节。成功位图仅说明补丁在锁存错误前未接受对应成功 ED，不能证明总线没有任何后续事件。

事件指针 `80023000` 与发布前 context 的 dequeue 指针一致。最新首虚拟 TRB `135897D000` 在日志所报告的模块范围内，context 的 state1/type5/interval1/MPS256/MaxESIT256 等配置符合候选。它们是软件快照，不构成独立 DMA 映射或物理来源认证。

重新汇编实际 `iso_burst_context.S`，全部22条 IPS 编辑与回收卡上的 IPS 逐字节相等，680字节注入体及反汇编已封存。该事件路径在非成功码分支写入错误偏移与 terminal，保存原始事件后直接返回；只有接受满3072字节成功 ED 的路径才调用原 completion。后续事件因 terminal 非零而返回，错误不会被后来的 ED 成功覆盖。

设备轮询实际调用 GetReportData 并交给 channel8 所有权观察器。报告 id387/status2 保持 active；ISO7 错误保留标记使 STATUS 进入 RETAINED。30秒窗口结束时诊断 pending1、owner_finish=false 因而与这条分支自洽。它无需用“没有轮询”或“所有权观察器漏掉成功报告”来解释，但目前材料也没有完整的每次报告历史。

这里保留 **设备 CC23** 的原始编号，不把主机 xHCI 的同号名称直接当作该设备控制器的已证实语义。

| --- | ---: | ---: | ---: | ---: | ---: | --- |

每次 host首帧=current+64，设备目标帧=(选帧MFI>>3)+32（mod2048）。三个样本的设备选帧整帧都比 host current低11位多1，设备目标帧都位于 host sample之后33帧。条件比较下，host窗口晚31帧，首 TD 参考槽为 **-248**，落在当前960槽窗口之前。错误handler MFI 都为设备目标帧起点+8微帧，即下一整帧的读数。

本机 SDK 头文件明确 frameNumberWithTime 返回不含微帧的控制器帧号，firstFrameNumber 是请求起始帧；相关头文件已复制封存。它支持 API 单位解释，不能独立对齐两端时钟或证明真实总线服务时间。MFI 来自 handler 读寄存器的时刻，也不是错误发生时刻。历史 libusb 接收器有明显不同的控制请求延迟，不能把其 host64 成功直接外推到当前快速 SDK 路径。

## 下一步候选与验证条件

先离线准备 **host首帧提前到 current+32** 的独立候选，保持设备包、补丁、192字节请求、960槽和单次原则。仅为验证覆盖假设，不先改设备完成/释放路径，也不增加延时掩盖问题。

| 条件模型中的主机lead | 首TD参考槽 | 调度约束 |
| ---: | ---: | --- |
| 64（现状） | -248 | 三份样本均在接收窗口前 |
| 32（优先候选） | 8 | 需新预算及显式lead绑定 |
| 24 | 72 | 旧入队最坏24ms已无提前余量 |
| 16 | 136 | 旧入队预算可能允许窗口开始后才入队 |

上述16槽仅为条件参考位置；TD1..15的 SIA 不保证实际逐槽服务。旧预算允许 frame_age16ms + enqueue8ms，且 control完成年龄48ms与reserve16ms是基于lead64的组合；因此不能只替换常量后复用旧断言。lead32需要独立审查入队余量、触发前检查、16ms控制期限与保留余量的关系，以及拒绝后已提交ISO的资源收尾。新的 schema/材料/分析器须显式绑定lead32并拒绝旧64回执，旧工具与零次数记录保持。

候选离线检查至少覆盖：帧/微帧及2048回绕、窗口前后边界、过期/慢入队拒绝、控制超时、错误保留不释放、旧计划拒绝，以及同一原始数据在64与32条件模型中的不同参考位置。准备完成后才安排另一次明确开始的诊断；不自动签发或执行。

未来可区分的结果：若提前窗口后取得16包精确载荷、设备 bitmapFFFF/actual3072/terminal1 与自己的URB/status3，可支持窗口假设；若仍是首TD CC23且零载荷，优先补充设备发布至doorbell/错误时的有界帧读数及原始事件来源。只有回调状态0、进入COMPLETE或某些空槽为0均不能通过验收。两端独立帧对齐、静默报告全历史与物理总线证据仍有缺口。
